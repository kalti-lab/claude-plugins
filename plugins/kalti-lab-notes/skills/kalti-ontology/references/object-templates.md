# 온톨로지 객체 템플릿

`ontology/<종류>/`에 객체를 만들 때 쓴다 — 종목은 `ontology/종목/`, 가설은 `ontology/가설/` 식으로 종류마다 폴더가 있고, **파일 이름에는 종류를 붙이지 않는다**(붙임표가 이름 안에서도 쓰여 `개념-`이 이름 첫 낱말인지 종류인지 구별되지 않았다). 링크는 **파일 이름**으로 건다. id는 frontmatter 안에서만 쓰고 링크에는 쓰지 않는다. `#` 주석은 실제 파일에서 지운다.

## 종목 (project)

```markdown
---
id: proj-
title:
type: project
status: 진행      # 진행 / 보류 / 완료 / 보관
tags: []
updated:          # YYYY-MM-DD. 카드를 고칠 때마다 갱신
---

# (제목)

(이 종목이 무엇을 목표로 하는지 한 문단)

## 현재 가설
- [[(가설 노트 이름)]]

## 실험
- [[(실험 일지 이름)]]

## 발견
- [[(발견 노트 이름)]]

## 참여
- [[(사람 노트 이름)]]
```

## 가설 (hypothesis)

```markdown
---
id: hyp-
title:
type: hypothesis
status: 제안      # 제안 / 채택 / 기각 / 대체됨
# closed:         # YYYY-MM-DD. 채택·기각·대체된 날 — 상태가 제안이 아니게 되는 순간 넣는다.
#                 # 본문 `## 상태` 줄에도 같은 날짜를 적지만, 기계가 세는 쪽은 이 칸이다.
partOf: "[[(종목 노트 이름)]]"
# supersedes: "[[(옛 가설 노트 이름)]]"   # 대체하면
# concept: "[[(개념 노트 이름)]]"       # 종목을 넘나드는 개념에 속하면
tags: []
updated:          # YYYY-MM-DD
---

# (제목)

(가설을 한 문장으로)

## 상태
제안 (YYYY-MM-DD)

## 근거
(어느 실험·발견이 근거인지)
```

## 발견 (finding)

```markdown
---
id: find-
title:
type: finding
date:             # YYYY-MM-DD
partOf: "[[(종목 노트 이름)]]"
derivedFrom: "[[(실험 일지 이름)]]"
# supports: "[[(가설 노트 이름)]]"   # 뒷받침하면
# refutes: "[[(가설 노트 이름)]]"    # 반박하면
# concept: "[[(개념 노트 이름)]]"    # 종목을 넘나드는 개념에 속하면
tags: []
updated:          # YYYY-MM-DD
---

# (제목)

(결론을 한 문장으로)

(메커니즘·근거 문단)
```

## 개념 (concept)

```markdown
---
id: con-
title:
type: concept
# role: glossary   # 종목을 잇는 허브가 아니라 낱말 뜻만 적는 글이면 이 줄을 살린다.
#                  # 개념 수·드리프트 검사에서 빠진다.
tags: []
updated:          # YYYY-MM-DD
---

# (제목)

(이 개념이 무엇인지 쉽게 3~5문장. 우리 연구에서 왜 중요한지)

## 이 개념에 도달한 발견

**(이 개념이 취하는 형태 1)**
- [[(발견 노트 이름)]] — (그 발견의 한 줄 결론)

**(형태 2)**
- [[(발견 노트 이름)]] — (그 발견의 한 줄 결론)

## 함께 보기
- [[(경계가 맞닿는 다른 개념)]]
```

소속을 선언하는 쪽은 발견·가설의 `concept:` 필드다. 위 목록은 그중 **설명할 값이 있는 것만 골라 형태별로 묶은 큐레이션**이고 전체 명단이 아니다(전체는 `obsidian backlinks`로 읽는다). 그래서 이 목록을 기계로 다시 쓰면 안 된다 — 형태 분류가 이 카드의 값이다.

## 결정 (decision)

```markdown
---
id: dec-
title:
type: decision
status: 유효      # 유효 / 번복됨
# reversed:       # YYYY-MM-DD. 번복된 날 — 상태를 번복됨으로 바꾸는 순간 넣는다.
date:             # YYYY-MM-DD. 정한 날
partOf: "[[(종목 노트 이름)]]"
derivedFrom: "[[(그 결정이 적힌 일지 이름)]]"
# supersedes: "[[(뒤집은 옛 결정 이름)]]"   # 앞선 결정을 갈아치우면
# basedOn: "[[(발견 노트 이름)]]"          # 근거가 된 발견·가설이 있으면
tags: []
updated:          # YYYY-MM-DD
---

# (제목)

(무엇을 정했는지 한 문장. "~하기로 했다"로 끝난다)

## 왜
(그 결정을 만든 이유. 값·수치가 근거면 그대로 적는다)

## 대신 버린 것
(같이 검토했다가 안 고른 것과, 왜 안 골랐는지.
 이게 없으면 몇 달 뒤에 버린 쪽을 다시 검토한다)

## 되돌리는 조건
(무엇이 관찰되면 이 결정을 다시 볼 것인가. 없으면 "없음"이라고 적는다.
 조건을 미리 못박아 두지 않으면 되돌릴 때가 와도 아무도 눈치채지 못한다)
```

결정은 가설과 다르다. 가설은 **참인지 재는 것**이고 결정은 **고른 것**이다. 그래서 기각·채택이 아니라 유효·번복됨이고, 재서 틀렸다고 지우지 않는다 — 번복해도 옛 결정은 남고 새 결정이 `supersedes`로 가리킨다. 그때 왜 뒤집었는지가 새 결정의 "왜"에 들어간다.

## 자료 (source)

```markdown
---
id: src-
title:
type: source
url:
tags: []
updated:          # YYYY-MM-DD
---

# (제목)

(무엇인지 + 어디서 보는지(URL) + 우리 연구에 어떤 대목이 쓸모인지)
```

## 사람 (person)

```markdown
---
id: per-
title:            # 폴더 이름과 같게 (예: aram) — journals/<이 이름>/
type: person
name:             # 사람 이름 (예: 김아람)
role:             # 직책
worksOn:          # 참여 종목 전부. 한 줄에 하나씩
  - "[[(종목 노트 이름)]]"
tags: []
updated:          # YYYY-MM-DD
---

# (제목)

(한 줄 소개 — 무엇을 하는 사람인지보다 **어떻게 일하는 사람인지**를 적는다.
 "결과물 품질보다 재현 가능한 환경을 먼저 잡는 쪽" 같은 것)

## 주로 보는 것
- (주제) — (그 주제에서 실제로 한 일) ([[종목]] · [[종목]])
```

연락처(이메일·전화)는 넣지 않는다. 이 볼트는 위키 사이트로 나갈 수 있고, 한 번
나가면 되돌릴 수 없다.
